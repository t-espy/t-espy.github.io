Autonomous Improvement Rate

A simple model for how fast autonomous systems can get better

First published: August 27, 2026

A system improves by trying things, learning something from the results, and using what it learned the next time around. That suggests a simple way to think about the speed of autonomous improvement:

RA ≈ Et × IE × ηL

Improvement Rate ≈ Iteration Throughput × Information per Iteration × Learning Efficiency

Where:

  • Et — Iteration throughput: How many experiments, attempts, simulations, builds, or other useful iterations can the system complete per unit of time?
  • IE — Information per iteration: How much useful information does each iteration produce? Running more experiments is not helpful if they teach you nothing.
  • ηL — Learning efficiency: How effectively does the system retain what it learned and use it to make future iterations better?

Why multiplication matters

These aren't three independent scorecards. They compound.

Suppose a system becomes 10× faster at running experiments, 2× better at choosing informative experiments, and 3× better at retaining and exploiting the results. The improvement rate doesn't rise by 15×. In this simple model, it rises by roughly 60×.

That is the important part of the equation. Modern autonomous systems can improve all three terms at the same time.

Software is the fast loop

Software development makes this easy to see. An AI coding system can write code, compile it, run tests, inspect the failures, modify the code, and try again. An iteration may take seconds or minutes. Failed experiments are cheap and usually reversible. Thousands of independent loops can run in parallel.

Simulation and computational research have many of the same properties. Instead of compiling code, the system runs a model or experiment. Instead of a unit-test result, it gets measurements. The loop is fundamentally similar:

propose → execute → measure → evaluate → learn → repeat

Physical systems use the same loop, but the clock runs slower. Automated laboratories must move samples and wait for reactions. Robots must interact with real objects. Vehicles have safety constraints. Manufacturing consumes materials and energy. Physical mistakes cost more than failed software builds.

So I expect autonomous improvement to advance fastest where iteration is cheap and feedback is objective: software first, then simulation and computational research, followed increasingly by automated laboratories, robotics, manufacturing, and other physical systems.

The scarce-resource version

There is another useful way to look at the same idea. Autonomous systems should not merely maximize output. They should maximize completed useful work per unit of whatever resource is actually scarce.

In an AI software factory, local compute may be abundant while access to the most capable frontier models is limited or expensive. A useful operating metric is therefore:

Autonomous Completed Work / Frontier-Model Token

Cheap local models can perform large numbers of implementation and test iterations. More capable models can be reserved for architecture, difficult decisions, review, and escalation. As the autonomous loop improves, more work completes without consuming the scarce resource at all.

The flywheel

The most interesting case is when the autonomous system works on itself. Better orchestration produces more successful autonomous work. That work improves the orchestration system. The improved system then produces useful work faster and with fewer expensive interventions.

better system → more autonomous work → faster system improvement → better system

Software and simulation are likely to show this effect first because their feedback loops are so fast. But the principle is broader: wherever a system can act, measure the result, retain the evidence, and use it to choose a better next action, the Autonomous Improvement Rate provides a simple way to think about what controls the speed of the flywheel.

Relationship to earlier work

This formulation has clear antecedents. Self-driving-laboratory research has separately identified three closely related axes: experiments per unit time, information gained per experiment, and the efficiency of converting experimental data into scientific knowledge. Work on active learning, Bayesian experimental design, and high-throughput experimentation develops individual parts of the same picture.

The claim made here is the generalization: treat these three factors as a simple multiplicative model for the rate of improvement of autonomous systems generally — not only laboratory experiments, but software development, computational research, simulation, robotics, and eventually autonomous physical production.

In that generalized form:

RA ≈ Et × IE × ηL

Prior-art note

A particularly close antecedent is Lee et al., Toward self-driving laboratory 2.0 for chemistry and materials discovery, Materials Horizons (2026), DOI: 10.1039/D5MH01984B. That review describes self-driving laboratories as advancing along three interdependent axes: experiment throughput, information gained per experiment, and efficiency of converting data into scientific knowledge. The Autonomous Improvement Rate proposed here extends that decomposition beyond self-driving laboratories into a domain-independent model of autonomous improvement.
