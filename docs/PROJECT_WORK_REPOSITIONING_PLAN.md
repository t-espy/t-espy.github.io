# Project Work Portfolio Repositioning Plan

## Decision

Reposition the site from an employment-oriented AI Platform Engineer profile to a buyer-facing portfolio for independent technical project work. Breadth is the central proof: the same problem-solving and delivery discipline has produced business automation, commercial products, AI systems, research infrastructure, performance improvements, and enterprise platforms.

The site will sell completed outcomes rather than labor categories. It will welcome focused fixed-price projects and larger systems divided into independently scoped phases.

## Audience and positioning

The primary reader is a problem owner evaluating whether Todd can understand, bound, and deliver a technical solution. Recruiters remain secondary readers. The primary promise is: "Bring me a difficult technical problem. I will turn it into a working, tested, deployable solution."

Supporting evidence includes thirty-plus years of delivery; current Python, C#, TypeScript, cloud, database, AI, and local-inference work; controlled AI-assisted development; completed systems across unrelated domains; and an MSEE, physics degree, AWS certifications, patents, publications, recognition, and enterprise delivery.

## Information architecture

Global navigation: Home, Services, Projects, How I Work, Credentials, Writing, Contact. Existing technical case studies remain available beneath those destinations. Individual project names no longer consume global-navigation positions.

The homepage moves through buyer-oriented promise, problems solved, selected work, delivery method, experience, project fit, and project inquiry. The Projects page groups work as Complete Products and Business Automation; AI and Autonomous Development Systems; Research Evaluation and Performance Engineering; and Enterprise Systems and Long-Term Track Record.

## Contact behavior

The primary action opens an email to `todd.espy@gmail.com` with a prefilled subject and prompts for the problem, current state, desired outcome, available code/systems/data, deadline, and constraints.

## Delivery phases

### Phase 1 Commercial front door

- Rewrite the homepage.
- Replace global navigation with buyer-oriented destinations.
- Add Services, Projects, How I Work, Writing, and Contact pages.
- Extend shared styling and update the browser test.

### Phase 2 Case-study normalization

- Give every substantial project a full case-study page or verified external link.
- Normalize around problem, solution, evidence, constraints, and demonstrated client capability.
- Add visuals only when they materially improve understanding.

### Phase 3 Conversion evidence

- Add privacy-respecting inquiry and navigation analytics.
- Measure inquiry sources, project categories, qualified conversations, wins, effort, and realized economics.
- Change emphasis only when buyer behavior justifies it.

## Phase 1 acceptance criteria

- No homepage language asks the reader to consider Todd for a role.
- The first screen establishes independent technical project delivery.
- Buyer problems are understandable without opening another page.
- Every substantial recent project is represented or reachable from Projects.
- Contact opens a structured project-inquiry email.
- Existing case studies remain reachable.
- Desktop and mobile navigation expose seven buyer-oriented destinations.
- Static browser checks pass.
